# Peach Girl Store - Apps Script 後端移植說明

本資料夾的後端程式拆成多個 Apps Script 檔案，所有 .gs 檔案必須放在**同一個 Google Apps Script 專案**。

## 檔案用途

| 檔案 | 用途 |
| --- | --- |
| Code.gs | Apps Script 網頁入口：doGet、bridgeCall、doPost |
| Config.gs | 工作表名稱、欄位設定 |
| Database.gs | Google Sheets 初始化與共用讀取 |
| ApiRouter.gs | API 動作分派 |
| AdminService.gs | 管理員登入與權限 |
| MemberService.gs | 會員註冊、登入、登出、Session |
| CommerceService.gs | 會員購物車與收藏同步 |
| SecurityService.gs | 密碼與 Token 雜湊 |
| ProductService.gs | 商品查詢、儲存、上下架 |
| DriveService.gs | 商品圖片上傳至 Google Drive |
| HttpService.gs | JSON 回應 |
| Bridge.html | 前端 iframe 橋接，必須保留原檔 |

## 移植方式

1. 開啟原本的 Google Apps Script 專案。
2. 將舊版 Code.gs 全文替換成 GitHub 中新版 Code.gs。
3. 新增上述所有 .gs 檔案，檔名照表格建立，貼上各檔案內容。
4. 保留既有 Bridge.html，不要刪除或改名。
5. 確認 Apps Script 指令碼屬性仍有 SPREADSHEET_ID、IMAGE_FOLDER_ID，以及管理員設定所需的屬性。
6. 執行 initializeStore()。它會建立缺少的工作表；本次會新增 Cart 工作表，既有資料不會被清空。
7. 檢查執行記錄沒有錯誤，再更新既有網頁應用程式部署版本。

## 重要注意

- 不要把不同 .gs 檔案建立成不同 Apps Script 專案；它們必須在同一專案內。
- Apps Script 的 .gs 檔案共用全域命名空間，不使用 Node.js 的 import/export。
- Bridge.html 是前端唯一橋接頁，請保留。
- 本次不需要修改前端 api.js，也不需要更改 VITE_API_BASE_URL。
- initializeStore() 只會替「完全空白」的工作表寫入標題列，不會自動修改既有工作表的欄位順序。
- Members 欄位順序必須維持：member_id、username、email、password_hash、password_salt、display_name、phone、status、created_at、updated_at、last_login_at。
- 會員註冊使用電子郵件作為 username 與 email；登入以 email 欄位比對。
- 會員密碼至少 12 個字元。前端只儲存登入 Token，不會儲存會員密碼。
- Favorites 與 Cart 依 member_id 隔離；訪客購物車與收藏先保存在瀏覽器，登入後合併至會員資料。購物車相同商品與規格會合併數量，收藏採合併去重。
- 新增 CommerceService.gs，並更新 Config.gs、ApiRouter.gs；三者都必須同步到同一個 Apps Script 專案。
- 移植後請先測試商品讀取、管理員登入，再測試會員註冊、登出、重新登入與重新整理後的登入狀態。
